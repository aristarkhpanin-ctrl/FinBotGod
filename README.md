# Исследовательская торговая система для Мосбиржи

Инфраструктура для проверки торговых гипотез на российском рынке акций
с честным учётом издержек. Полное техническое задание: [docs/TZ_trading_system.md](docs/TZ_trading_system.md).

> Главный продукт — не прибыль, а достоверный ответ на вопрос
> «работает ли эта идея после издержек». Порог безубыточности при
> капитале 20 000 ₽ — около **38% годовых**, и система показывает
> эту цифру в каждом отчёте.

## Состояние проекта

| Фаза | Статус |
|---|---|
| 1. Слой данных MOEX ISS | **Готово** (код и тесты; загрузка данных — см. ниже) |
| 2. Модель издержек | **Готово** |
| 3. Сайзинг и лотность | Заглушка |
| 4. Движок бэктеста | Заглушка |
| 5–9, Часть II (ML) | Заглушки, выключены флагом `ml.enabled: false` |

## Как запустить

Нужен Python 3.11 или новее.

```bash
# 1. Установить зависимости
pip install pandas numpy httpx pydantic-settings PyYAML structlog pyarrow pytest

# 2. Прогнать тесты (сеть не нужна)
python -m pytest

# 3. Скачать данные Мосбиржи (нужен доступ к iss.moex.com)
python scripts/download_universe.py
```

Скрипт скачивает дневные свечи по 35 бумагам из `trading/config/universe.yaml`
за 2015–2026, сохраняет их в `data_cache/` (Parquet) и печатает отчёт
валидации: аномалии в данных, подозрительные скачки цены (возможные сплиты),
пропуски, лотность. **Повторный запуск не делает ни одного сетевого
запроса** — всё берётся из кэша. Обрыв сети посреди загрузки кэш не портит:
можно просто запустить скрипт ещё раз.

## Панель управления

Единственный файл, который нужно редактировать, —
[`trading/config/settings.yaml`](trading/config/settings.yaml).
Каждый параметр подписан по-русски с единицами измерения. Ошибка в
конфиге приводит к отказу запуска с объяснением, а не к падению.

Стресс-тест издержек: поставить `стресс_множитель: 2.0` — все издержки
удвоятся. Стратегия, умирающая при удвоении издержек, не имеет запаса
прочности.

## Что уже защищает от самообмана

- **Модель издержек в ядре**: комиссии, спред, проскальзывание, растущее
  с размером заявки; заявка больше 5% дневного оборота отклоняется как
  нереализуемая (`trading/core/costs.py`).
- **Журнал гипотез**: каждый прогон записывается с хешем конфигурации и
  данных; отключить нельзя, удалить запись нельзя; сводка показывает
  медиану по всем конфигурациям, а не только лучшую
  (`trading/research/ledger.py`).
- **Реестр признаков**: признак без явно указанной задержки доступности
  данных (`availability_lag`) не регистрируется — защита от утечки
  будущего (`trading/features/registry.py`).
- **Валидация данных**: дубликаты, битые свечи, пропуски, детектор
  сплитов — всё в отчёте, ничего молча (`trading/data/validation.py`).

## Структура

```
trading/
├── config/         настройки (панель управления) и белый список бумаг
├── data/           клиент MOEX ISS, кэш Parquet, валидация, универсум
├── core/           модель издержек (готово); сайзинг, портфель (фаза 3–4)
├── research/       журнал гипотез (готово); LLM (Часть II)
├── features/       реестр признаков (готово); хранилище (Часть II)
├── ml/             Часть II, выключено фича-флагом
├── strategy/       интерфейс стратегии (реализация — фаза 4)
├── risk/           риск-слой (фаза 6)
├── engine/         backtest / paper / live (фазы 4, 8, 9)
├── execution/      абстракция исполнения; ALOR (фаза 9)
└── reporting/      отчёты; порог безубыточности — уже в каждом отчёте
scripts/            download_universe.py — загрузка данных с отчётом
tests/              70 тестов, работают без сети
```
